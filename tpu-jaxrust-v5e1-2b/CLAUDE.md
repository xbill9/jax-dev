# CLAUDE.md — TPU Management Skill & tpu-jaxrust-v5e1-2b MCP Agent

Guidance for Claude Code when working in this repository.

## This rig

`tpu-jaxrust-v5e1-2b` serves `google/gemma-4-E2B-it` (bf16) on one TPU v5e chip with the forward pass written in Rust: `rust/src/gemma.rs` builds the graph, `rust/src/hlo.rs` emits it as StableHLO text, and libtpu's PJRT plugin (the one JAX loads) compiles and runs it through `rust/src/pjrt.c`, a C shim over the vendored PJRT C API header. A PyO3 module, `jaxrust_rs`, exposes it to Python. No JAX in the model path. Sister rig: `../tpu-jax-v5e1-2b`, the same checkpoint on the same chip through the Python JAX engine; `tools/parity.py` runs both and compares them. `server.py` is the one shared with that rig and the `q4w4a16` rigs.

#### Rules the code depends on

- **Every PyO3 item is in `rust/src/bindings.rs`.** `gemma.rs`, `hlo.rs`, `pjrt.rs`, `weights.rs` stay free of Python types. Keep `rust/PYO3.md` and `rust/python/jaxrust_rs.pyi` in step with it; `tests/test_rust_bindings.py` checks the export list against the stub.
- **The graph mirrors `../tpu-jax-v5e1-2b/ports/gemma4/jax_e_model.py`, element types included.** `hlo.rs` promotes bf16 to f32 where JAX does, and `scale`/`add_scalar` keep the operand's type the way a Python float does in JAX. A change to the JAX model needs the same change here, then a parity run.
- **MLIR text rules learned on the chip:** a float literal needs a `.` (`2.0e0`, never `2e0`), and an empty integer array is `array<i64>`, never `array<i64: >`. Both fail at PJRT compile with a line and column into the emitted module; `jaxrust_rs.emit(dir, kind, s, t)` returns that module to read.
- **Compile options are 6 hand-encoded bytes** (`pjrt.rs` `COMPILE_OPTIONS`: one replica, one partition). Empty options make libtpu ask for 0 cores.
- **The KV cache is donated** (`tf.aliasing_output` on each cache argument) and slot equals position: decode starts at the prompt's real length and overwrites the bucket's pad slots.
- `Engine` is `#[pyclass(unsendable)]`: build it and call it on one thread. One process holds the TPU.

## Project Overview

This repository packages one Claude Code skill (`tpu-jaxrust-v5e1-2b-management`) and one **Model Context Protocol (MCP) server** (`tpu-jaxrust-v5e1-2b`, an MCPServer app in `server.py`). Together they:

1. **Operate TPU infrastructure:** find, provision, and destroy Google Cloud TPU capacity (flex-start VMs, queued resources) and run Gemma 4 vLLM serving on it.
2. **Run bare JAX on TPU:** provision flex-start VMs with `workload="jax"` — the startup script installs a current CPython + `jax[tpu]` and asserts a TPU device is visible (`wait_for_jax_ready`, `verify_jax_tpu`). No docker, no HF token.
3. **Do SRE diagnostics:** verify model health, fetch vLLM/system/Cloud Logging logs, and use the self-hosted Gemma 4 model to triage them (`analyze_cloud_logging`).

## Repository Layout & the Snapshot Sync Model

The repo-root files are authoritative; the skill is distributed as generated copies. **Edit the sources, then run `make skill` — never edit a snapshot directly.**

- **Sources (root):** `server.py` (the MCP server), `project-setup.sh` (installer), `requirements.txt`, `tpu.md` (TPU getting started guide; gitignored, private). The guide's prose is kept vendor-neutral — no Google branding or TPU Builders Program references; only functional `gcloud` commands, API endpoints, and doc/console URLs may contain "google". Preserve that when editing `tpu.md`.
- **Hand-maintained (not regenerated):** `.claude/skills/tpu-jaxrust-v5e1-2b-management/SKILL.md`, `.claude/skills/tpu-jaxrust-v5e1-2b-management/mcp/startup_script_template.sh`, `.claude/skills/tpu-jaxrust-v5e1-2b-management/mcp/startup_script_jax_template.sh`
- **Generated by `make skill` (`refresh_skill.py`):**
  - `.claude/skills/tpu-jaxrust-v5e1-2b-management/mcp/{server.py,project-setup.sh,requirements.txt}` — copies of the root sources
  - `.claude/skills/tpu-jaxrust-v5e1-2b-management/references/tpu-guide.md` — `tpu.md` with base64 screenshots stripped
  - `skills/tpu-jaxrust-v5e1-2b-management/` — full copy of the skill in plugin layout (for the marketplace)
- **Generated, gitignored:** `.mcp.json` (embeds the GCP project id) — created by `./init.sh` on first run, or regenerated with `./project-setup.sh . --project <id> [flags]`; never commit it or hand-edit it back into git.
- **Plugin marketplace:** `.claude-plugin/plugin.json` + `.claude-plugin/marketplace.json` make the repo installable via `/plugin marketplace add xbill9/tpu-skill-claude`. Validate changes with `claude plugin validate .`
- **Distribution zip:** `dist/tpu-jaxrust-v5e1-2b-management-skill.zip`, built by `make skill-package`; committed so the raw-GitHub-URL install works — rebuild it when the skill changes

## Technical Standards: vLLM & Gemma 4 Tool Calling

When managing TPU deployments or customizing vLLM serving, apply these vLLM parameters for stable Gemma 4 tool integration:

- **Optimization flags:** `--tensor-parallel-size 8` (TPU v6e-8), `--disable_chunked_mm_input`, `--max-model-len 16384`
- **Tool parsing:** `--enable-auto-tool-choice`, `--tool-call-parser gemma4`, and `--reasoning-parser gemma4` for native function-calling compatibility
- **Multimodal configuration:** `--limit-mm-per-prompt '{"image":4,"audio":1}'` and `--max_num_batched_tokens 4096`
- **Universal SRE help:** the agent exposes a standardized `get_help` tool describing its active configuration environment variables and all exposed tools

## Coding Standards

- **No virtualenvs:** use the system `python3`; if dependencies are missing, warn with the `pip install -r requirements.txt` command instead of creating a venv (this is also how `project-setup.sh` behaves).
- **Dependency portability:** do not assume third-party libraries like `pandas` are installed. Prefer the standard library (`csv`, `json`) for data parsing and aggregation scripts.
